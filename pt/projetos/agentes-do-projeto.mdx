Dentro de um projeto, os agentes só enxergam **o que é do projeto**. Esta página explica, de forma simples, **quem acessa o quê**: o agente do projeto e os agentes que você adiciona a ele têm acesso ao contexto do projeto; agentes que estão **fora** do projeto não têm — mesmo que sejam poderosos em outros lugares da empresa.

## O agente do projeto

Todo projeto pode ter um **agente do projeto** — o especialista daquele contexto. Ele é quem **mede os KPIs**, responde no chat do projeto e trabalha os objetivos, sempre com acesso ao conhecimento e aos dados **daquele** projeto.

<Info>
O agente do projeto enxerga só o mundo do projeto. Ele não puxa conhecimento da empresa nem de outros projetos — a menos que você tenha ligado algo explicitamente (por exemplo, um objetivo com **"Deriva de"**).
</Info>

## Quem enxerga o contexto do projeto

<CardGroup cols={2}>
  <Card title="Agentes DENTRO do projeto" icon="circle-check">
    O agente do projeto e os agentes/times que você **adicionou** ao projeto podem acessar o **conhecimento**, os **objetivos**, as **ações**, os **resultados** e os **dados** do projeto.
  </Card>
  <Card title="Agentes FORA do projeto" icon="circle-xmark">
    Qualquer agente que **não** faz parte do projeto **não** enxerga nada disso. Para ele, o conteúdo do projeto simplesmente não existe.
  </Card>
</CardGroup>

## Como adicionar um agente ao projeto

<Steps>
  <Step title="Abra o painel de agentes do projeto">
    No projeto, use o painel de **agentes e times** à direita.
  </Step>
  <Step title="Adicione o agente ou time">
    Escolha entre os agentes/times a que você tem acesso. A partir daí, ele passa a fazer parte do projeto e a enxergar o contexto dele.
  </Step>
  <Step title="Use-o dentro do projeto">
    Clique no agente para abrir o chat já no contexto do projeto. Ele responde com base no conhecimento e nos objetivos do projeto.
  </Step>
</Steps>

## O isolamento, explicado simples

Pense em cada projeto como uma **sala fechada**. Dentro da sala estão os documentos, as metas e os dados daquele projeto. Só quem está **na sala** (o agente do projeto e os agentes que você colocou lá) enxerga o que há dentro. Quem está do lado de fora não vê nada — e um agente que está em duas salas diferentes **nunca** leva conteúdo de uma para a outra.

<Warning>
O isolamento não é só "esconder na tela". A busca de conhecimento e a medição de KPIs são **escopadas ao projeto** no próprio mecanismo: um agente de fora não consegue trazer, na resposta, conteúdo de um projeto do qual não faz parte.
</Warning>

## Isolamento entre projetos

Um mesmo agente pode participar de **vários projetos**. Em cada um, ele só enxerga o contexto **daquele** projeto. Ele nunca cruza informações — o que aprendeu ou leu no Projeto A não vaza para o Projeto B.

## Alçada das pessoas

O acesso dos agentes anda junto com a alçada das **pessoas**:

- Quem tem acesso ao **projeto** vê os agentes e o conteúdo do projeto (respeitando o acesso a cada agente).
- **Dono/Admin** da empresa enxergam os projetos conforme as regras de acesso da empresa.
- Conceder acesso a alguém ao projeto é uma forma prática de liberar, de uma vez, os recursos ligados a ele. Veja [Segurança & Acessos](/pt/administracao/seguranca-e-acessos).
