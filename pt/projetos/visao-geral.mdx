Um **Projeto** é um **espaço de trabalho** dentro do iTeam, dedicado a um cliente, uma área, um produto ou uma iniciativa. Tudo o que acontece ali — conversas, objetivos, conhecimento, arquivos e tarefas — vive **dentro do projeto** e não se mistura com o resto da empresa. É a forma prática de organizar o iTeam por contexto: cada projeto é um "mundo" próprio, com os agentes certos e as informações certas.

## Para que serve um projeto

<CardGroup cols={2}>
  <Card title="Organizar por contexto" icon="folder-kanban">
    Reúna num só lugar tudo o que pertence a um cliente, área ou iniciativa — sem poluir a empresa inteira.
  </Card>
  <Card title="Isolar o que é sensível" icon="shield">
    Objetivos, conhecimento e arquivos do projeto ficam **exclusivos** dele. Quem não está no projeto não vê.
  </Card>
  <Card title="Dar foco aos agentes" icon="crosshair">
    Os agentes do projeto trabalham só com o contexto do projeto — respostas mais precisas, sem ruído.
  </Card>
  <Card title="Herança de acesso" icon="key">
    Quem recebe acesso ao projeto **herda** os recursos ligados a ele — uma forma prática de liberar tudo de uma vez.
  </Card>
</CardGroup>

## As abas do projeto

Ao abrir um projeto, você encontra uma barra de abas no topo. Cada uma é um espaço de trabalho completo, restrito àquele projeto:

<AccordionGroup>
  <Accordion title="Chat" icon="messages-square">
    Converse com os agentes e times do projeto. O chat já entra no contexto do projeto: os agentes enxergam os objetivos, o conhecimento e os arquivos daquele projeto (e nada de fora dele).
  </Accordion>
  <Accordion title="Cortex" icon="target">
    O cérebro de gestão **do projeto**: Objetivos, Ações, Resultados, Aprendizados, Meetings, Conhecimento e Biblioteca — tudo isolado do Cortex da empresa. É a página principal de um projeto; veja [Cortex do Projeto](/pt/projetos/cortex-do-projeto).
  </Accordion>
  <Accordion title="App" icon="layout-dashboard">
    A interface (micro-app) do projeto, quando ele tem uma. Reúne os widgets e telas que os agentes montaram para o dia a dia daquele projeto.
  </Accordion>
  <Accordion title="Workspace" icon="folder-open">
    O espaço de trabalho compartilhado do projeto — o lugar onde as entregas e materiais colaborativos ficam à mão da equipe e dos agentes.
  </Accordion>
  <Accordion title="Storage" icon="database">
    Os dados e coleções do projeto. É onde ficam guardadas as informações que os agentes do projeto leem e gravam, isoladas de outros projetos.
  </Accordion>
  <Accordion title="Tarefas" icon="list-checks">
    O quadro de tarefas do projeto: o que está para fazer, em andamento e concluído — incluindo o que os agentes executam de forma assíncrona.
  </Accordion>
  <Accordion title="Processos" icon="git-branch">
    As rotinas automatizadas de várias etapas que rodam dentro do projeto.
  </Accordion>
  <Accordion title="Codes" icon="code">
    Os códigos e scripts do projeto, quando você precisa de lógica sob medida rodando de forma isolada.
  </Accordion>
</AccordionGroup>

<Info>
Nem todo projeto usa todas as abas. Comece pelo **Chat** e pelo **Cortex** — o resto vai aparecendo conforme a necessidade do projeto cresce.
</Info>

## O painel de agentes e times

À direita do projeto há um painel com os **agentes e times** que fazem parte dele. É a "equipe" daquele projeto.

<Steps>
  <Step title="Adicione agentes ou times ao projeto">
    Escolha entre os agentes/times a que você tem acesso. A partir daí, eles passam a fazer parte do projeto e enxergam o contexto dele.
  </Step>
  <Step title="Clique em um agente ou time para conversar">
    Clicar em um agente (ou time) no painel **abre o chat** já com ele selecionado, dentro do contexto do projeto. É o atalho para colocá-lo para trabalhar na hora.
  </Step>
  <Step title="Retire quem não precisa mais">
    Ao remover um agente do projeto, ele deixa de enxergar o contexto daquele projeto. Nada do que é da empresa é afetado.
  </Step>
</Steps>

<Tip>
Um mesmo agente pode participar de vários projetos. Dentro de cada projeto ele só enxerga o contexto **daquele** projeto — nunca cruza informações entre projetos.
</Tip>
